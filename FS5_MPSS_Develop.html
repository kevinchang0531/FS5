03 資料交換介面（Interface Control — CDRL-018） MCC ↔ SOCC 各子系統
資料流 方向 外部系統 格式／協定 說明
RSI Mission Timeline IN PSS（影像計畫排程） XML RSI 任務時序表輸入，包含成像窗口、姿態需求、SSR 使用計畫
RSI Acquisition Schedule Report OUT PSS XML MCC 產出的解析排程報告，包含無衝突地面指令與上傳指令
AIP Mission Timeline IN AIP SDDC（資料發布） XML AIP 任務時序，包含播放計畫（Playback）與程序指令
AIP Acquisition Schedule Report OUT AIP SDDC XML AIP 排程確認報告，傳回可執行之排程結果
AIP Command Procedures IN AIP SDDC XML AIP 上行指令程序定義
Programming Requests（PRs） IN Customer / External OGC SPS 客戶影像程序請求，遵循 OGC Sensor Planning Service 標準（EO Satellite Tasking Extension）
Programming Proposals（PPs） OUT Customer OGC SPS TOFA 評估後回傳的可行性建議書，供客戶確認
Command Database（ARCOS） I/O MOC（任務操作中心） DB Interface MCC 驗證所產出指令載荷（Command Loads）時，需存取 MOC 的 ARCOS 指令資料庫
Orbit Events / FDF Data IN FDF（飛行動力設施） File / API 軌道事件（AOS/LOS 時序、星曆資料）輸入，作為排程計算基礎
Pass Plan / Resolved Schedule OUT MOC / RTS File / XML 每日至少一次產出，涵蓋下 24 小時的通訊過站計畫與衛星指令時序
04 主要功能（Key Functions） PRM ／ TOFA ／ MPSS 三模組
◆ PRM — Programming Request Manager
  • 依循 OGC SPS（Sensor Planning Service）標準接收客戶影像程序請求
  • GetCapabilities：揭露服務能力後設資料
  • DescribeTasking：提供 Submit 所需參數說明
  • GetFeasibility：判斷請求是否可行
  • Submit：接受正式任務委託
  • DescribeResultAccess：指示資料取用路徑
  • GetSensorAvailability / SubmitSegmentByID（EO Satellite Tasking Extension）
  • 採 RIA 前端（Rich Internet Application）供操作員使用
◆ TOFA — Tasking Order Feasibility Assessor
  • 將 PRM 接收的 Programming Requests 轉換為 Tasking Orders（TOs）
  • 評估 TO 的可行性（姿態限制、SSR 容量、過站窗口等）
  • 產出 Programming Proposals（PPs）回傳客戶確認
  • 與 FDF、MPSS、CWB 通訊取得評估所需資訊
  • 採用 Apache ServiceMix（SOA 架構）協調多服務工作流程：
  • ActiveMQ：可靠訊息傳遞
  • Apache Camel：訊息路由 / EIP
  • Apache CXF：WS-* / RESTful 服務
  • Apache ODE：WS-BPEL 業務流程引擎
  • Apache Karaf：OSGi 伺服器執行期
◆ MPSS — Mission Planning and Scheduling Subsystem
  • 建立短、長期任務排程（短期：24hr；長期：7天以上）
  • Session Management：工作階段與 Branch 管理，支援排程版本分支
  • Activity Request List Editor：編輯與管理活動請求清單
  • Cold Scheduling：自動排程初始產生
  • External Activity Request Scheduler（EARS）：接收 Mission Timeline 並排入
  • Gantt Chart（Hot Scheduling）：視覺化排程甘特圖與手動調整
  • Schedule Validator：規則驗證（SSR 容量、Duty Cycle、S-Band 傳輸機等）
  • Schedule Report Generator：RSI/AIP Acquisition Schedule、SSR/Duty Cycle 報告
  • 基於 NASA EUROPA Planning & Scheduling Framework
◆ 排程規則引擎（FORMOSAT-5）
  • FS5 活動類型（12 種）：
  • RSI Imaging（遙感成像）/ RSI Playback / RSI DDT
  • AIP Playback / AIP Procedure
  • Spacecraft Maneuver（姿態機動）
  • Real-Time Command / Miscellaneous Memory
  • Uplink / X-Band Crossover / Monitoring（SOH）
  • 資源排程規則：
  • SSR（固態記錄器）容量與讀寫規則
  • Duty Cycle 限制（成像工作比）
  • S-Band 傳輸機互斥規則
  • X-Band / S-Band 過站接觸規則
  • Branch 合併規則（Branch Merging）
  • 衛星 / 地面站資源 Parameter Set 管理
05 技術重點摘要（Technical Highlights） 開發語言 ／ 框架 ／ 資料庫 ／ 安全性
NASA EUROPA
MPSS 核心規劃排程框架。Plan Database（活動/狀態/物件/約束）+ Problem Solver（自動修復計畫缺陷）+ Declarative Modeling Language（NDDL）。表達力強、可延伸、配置彈性高。
Apache ServiceMix（SOA）
TOFA 採用服務導向架構，以 ServiceMix 整合 ActiveMQ（訊息佇列）、Camel（路由）、CXF（WS/REST）、ODE（BPEL 流程）、Karaf（OSGi 執行期），確保服務間鬆耦合與可靠訊息傳遞。
PostgreSQL + PostGIS
企業級開源關聯式資料庫（PostgreSQL），搭配地理資訊擴充（PostGIS）支援衛星覆蓋區域計算、影像收集範圍的空間查詢與地理運算。支援 Linux / Windows / Mac 跨平台部署。
OGC SPS 標準介面
PRM 遵循 OGC Sensor Planning Service（SPS）國際標準，提供標準化感測器規劃請求介面，並實作 Earth Observation Satellite Tasking Extension，確保與外部系統的互操作性。
安全機制
SSL：所有通訊加密傳輸。
Authentication & Authorization：使用者身份驗證與存取控制，確保只有授權人員可操作排程系統。
Java 套件架構
MPSS 分層套件設計：
mpss.jpa（JPA 持久層）、mpss.dao（資料存取）、mpss.ac（活動控制）、mpss.oe（軌道事件）、mpss.mtl（Mission Timeline）、mpss.resources（資源管理）、mpss.plan（計畫管理）、mpss.sched（排程引擎）。
Rich Internet Application（RIA）
前端採用 RIA 架構，提供桌面應用程式等級的操作體驗（Gantt Chart 視覺化、Activity Request 編輯器、Session 管理），在瀏覽器中執行，降低客戶端部署成本。
平台與開發語言
平台：跨平台（Linux / Windows）
語言：Java（主要後端）
資料庫：PostgreSQL + PostGIS
服務框架：Apache ServiceMix（OSGi）
資料保護與高可用性
SAN 儲存提供 RAID 6 冗餘、Hot Swap 熱插換、資料快照（Snapshot / FlashCopy）與磁碟陣列複製功能，確保排程資料損毀時可快速回復（RTO 最小化）。
